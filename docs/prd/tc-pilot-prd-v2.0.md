## 1. 제품 개요

### 1-1. 한 줄 정의

**TC Pilot**은 기획서 파일을 업로드하면 테스트 케이스를 자동 생성하고, 테스트 실행부터 이슈 등록까지 하나의 흐름으로 연결해주는 기획 테스트 도구이다.

### 1-2. 배경 — 왜 만드는가

웹기획자는 기획서를 작성한 후 반드시 기획 테스트(TC 작성 → 테스트 수행 → 이슈 등록)를 거친다. 현재 이 과정의 핵심 문제는 **"도구 간 단절"**이다.

현재 워크플로우는 이렇다:

1. 기획서(PPT)를 보면서 직접 TC를 작성한다. 정교성이 떨어지며 기획자 역량마다 편차가 크다.
2. 구글시트에서 테스트를 수행하며 P/F를 체크한다
3. FAIL이 발생하면 Mantis(이슈 트래커)에 가서 이슈를 **처음부터 수동으로** 작성한다
4. TC의 Steps와 기대결과를 이슈 등록 양식에 다시 복사 붙여넣기한다

이 과정에서 여러번 **복사 붙여넣기**가 발생하고, TC와 이슈 사이의 연결이 끊어지며, TC 양식이 매번 달라지고, 엣지케이스 누락이 기획자 개인 역량에 의존한다.

LLM을 직접 사용하는 것만으로는 이 문제의 **절반만 해결**된다. AI가 좋은 TC 텍스트를 만들어주지만, 넣는 문서의 질에 따라 정확도가 떨어질수있다 또 TC 생성 이후의 워크플로우(테스트 추적 → 이슈 등록 → 외부 시스템 연동)는 여전히 수동이다. **이 단절을 연결하는 것**이 TC Pilot의 존재 이유다.

### 1-3. 타겟 사용자

**주 사용자:** 웹기획자 / IT서비스 기획자 (나와 같은 역할)

- 기획서를 직접 작성하고, 기획 테스트를 수행하는 사람
- LLM을 업무에 활용하고 있지만 도구 간 연결이 비효율적이라고 느끼는 사람
- UIUX 감각은 있지만 전문 개발자는 아닌 사람

**부 사용자:** QA 엔지니어, 개발자

- 기획자가 생성한 TC와 이슈를 확인하고 대응하는 사람
- Notion 칸반보드에서 이슈 상태를 추적하는 사람

### 1-4. 해결하려는 핵심 문제 3가지

**문제 1: TC 품질의 불균일**
같은 기획자라도 피로도, 시간 압박에 따라 TC 품질이 들쭉날쭉하다. 특히 엣지케이스(권한, 빈 상태, 경계값, 동시성 등)는 체계적 점검 없이 경험에만 의존해서 누락이 빈번하다.

→ TC Pilot은 11개 엣지케이스 카테고리와 8단계 도출 프로세스를 시스템 프롬프트에 내장하여, 매번 일관된 수준의 TC를 생성한다.

**문제 2: TC ↔ 이슈 간 단절**
FAIL이 발생하면 TC에 있는 Steps, 기대결과를 이슈 트래커에 다시 수동으로 입력해야 한다. 이 과정에서 정보 유실, 중복 작성, TC-이슈 간 추적 불가 문제가 발생한다.

→ TC Pilot은 FAIL 클릭 시 해당 TC의 정보(화면코드, Steps, 기대결과)를 이슈 등록 양식에 자동으로 채워주고, 사용자는 실제결과와 심각도만 입력하면 된다.

**문제 3: 기획서 형식의 비표준화**
기획자마다 PPT 양식이 다르고, 같은 기획자도 프로젝트마다 다른 구조를 사용한다. LLM에 매번 "이런 형식의 기획서인데 TC를 만들어줘"라고 컨텍스트를 설명해야 한다.

→ TC Pilot은 파일(PPT/MD/XLSX)을 업로드하면 표준 스펙 양식으로 자동 변환하는 중간 단계를 두어, 어떤 형식의 기획서든 일관된 TC가 나오도록 한다.

## 2. 제품 요구사항

### 2-1. 핵심 사용자 플로우

전체 플로우는 5단계이며, 사용자는 이 흐름을 **순서대로** 경험한다.

```
파일 업로드 → 스펙 확인/수정 → TC 생성 → 테스트 실행(P/F) → 이슈 등록(Notion)
```

---

**[Step 1] 파일 업로드 & 스펙 구조화 변환** ✅ 구현완료

사용자가 기획서 파일(PPT, MD, XLSX)을 드래그앤드롭하면, AI가 파일을 분석하여 아래 표준 스펙 양식으로 변환한다.

| 필드 | 설명 | 구현 상태 |
| --- | --- | --- |
| 화면코드 | 화면 고유 식별 코드 (예: CS001) | ✅ |
| 화면명칭 | 화면 이름 (예: 스케줄러 MY WORK-미처리) | ✅ |
| 경로 | 네비게이션 경로 (예: 스케줄러 > MY WORK > 미처리) | ✅ |
| 화면타입 | 리스트 / 폼 / 상세 / 팝업 / 대시보드 | ✅ |
| 관련 권한 | 접근 가능 사용자 유형 (예: 관리자, 일반사용자, 결재자) | ✅ |
| 출력조건 | 데이터 노출 조건 | ✅ |
| 표시형식 | UI 표시 규칙 | ✅ |
| 클릭동작 | 인터랙션 정의 | ✅ |
| 비고 | 추가 참고사항 | ✅ |

변환 결과는 편집 가능한 테이블로 표시되며, 사용자가 확인/수정한 후 다음 단계로 진행한다.

지원 파일 형식:
- PPT/PPTX — jszip 기반 파싱 + AI 분석 ✅
- MD — 텍스트 파싱 ✅
- XLSX — SheetJS 데이터 추출 후 AI 분석 ✅

🆕 **추가 구현:** parseOnly 모드 (스펙 변환만 테스트하는 체크박스 옵션)

---

**[Step 2] TC 자동 생성** ✅ 구현완료

확인된 스펙을 기반으로 AI가 TC를 자동 생성한다.

- TC 도출 8단계 프로세스 적용 ✅
- 11개 필수 점검 엣지케이스 적용 ✅
- JSON 파싱 fallback 파서 ✅
- Rate-limit 및 AI 응답 안정성 처리 ✅

🆕 **추가 구현:** TC 배치 히스토리 (tc_batches)
- TC 생성 이력을 배치 단위로 관리
- TCTab에서 배치 목록(1depth) → 해당 배치의 TC 상세(2depth) 분리 표시

**TC 테이블 컬럼:** TC ID, 섹션, 기능그룹, 화면코드, 테스트관점, 우선순위, TC 제목, 사전조건, 테스트절차, 기대결과, P/F, 이슈메모 ✅

---

**[Step 3] 테스트 실행 & 추적** ✅ 구현완료

- 각 TC의 P/F 상태 드롭다운 (PASS/FAIL/진행중/미확인) ✅
- 상단 대시보드 실시간 집계 ✅
  - 총 TC 수, PASS, FAIL, 진행중, 미확인, 완료율
- 관점별/기능그룹별 필터 ✅
- 우선순위 툴팁 ✅

---

**[Step 4] FAIL → 이슈 등록** ✅ 구현완료

TC에서 FAIL을 선택하는 순간, 이슈등록 패널이 슬라이드로 열리면서 TC 데이터가 자동으로 매핑된다.

| TC 필드 | → 이슈 필드 | 구현 상태 |
| --- | --- | --- |
| 화면코드 + TC 제목 | 이슈 제목 | ✅ |
| 테스트 절차 (Steps) | 재현 순서 | ✅ |
| 기대결과 | 기대결과 | ✅ |
| TC ID | 관련 TC | ✅ |
| — | 실제결과 (사용자 입력) | ✅ |
| — | 심각도 (사용자 선택) | ✅ |
| — | 스크린샷 (파일첨부) | ✅ |

[AI 보강] 버튼: AI가 TC 맥락을 참고하여 이슈 텍스트 보강 ✅

---

**[Step 5] Notion 이슈 DB 전송** ✅ 구현완료

- Notion API POST /v1/pages 호출 ✅
- 이슈 DB 속성 자동 매핑 ✅
- Notion 페이지 URL 저장 (양방향 링크) ✅
- Notion 연동 실패 시 xlsx 다운로드 백업 안내 ✅

---

🆕 **[추가 구현] 관리자 인증 시스템**

- 관리자 로그인/로그아웃 (세션 쿠키 기반) ✅
- 비관리자 사용자에게 읽기 전용 모드 적용 ✅
  - 스펙 변환, TC 생성, 이슈 등록 등 쓰기 작업 시 로그인 안내 모달 표시
- 관리자 배지 및 상태 표시 ✅

### 2-3. 차기 스프린트 요구사항 (2차 개선)

아래 항목은 1차 MVP에서 구현되지 않았으며, 2차 개선에서 다룰 예정이다.

#### 🔜 다중 프로젝트 관리

현재 앱은 단일 기본 프로젝트(ensure-default)만 지원한다. 실무 활용을 위해 프로젝트 생성/전환/삭제 기능이 필요하다.

- 프로젝트 목록 화면 (프로젝트별 TC 수, 마지막 수정일)
- 신규 프로젝트 생성 (프로젝트명 입력)
- 프로젝트 전환 (현재 작업 프로젝트 변경)
- 프로젝트별 독립된 스펙/TC/이슈 데이터

#### 🔜 TC 편집 및 수정

현재 AI가 생성한 TC를 생성 후 수정하는 기능이 없다. TC 품질 보완을 위해 인라인 편집이 필요하다.

- TC 테이블 셀 인라인 편집 (제목, 절차, 기대결과 등)
- TC 수동 추가 (빈 행 삽입)
- TC 개별 삭제

#### 🔜 스펙 편집 개선

현재 스펙 변환 결과 테이블의 편집 UX가 제한적이다.

- 스펙 행 추가/삭제
- 편집 내용 Supabase 저장 (현재 state 기반만)

#### 🔜 이슈 상태 관리

현재 이슈는 Notion에만 등록되며 웹앱 내 상태 변경이 없다.

- 이슈 로그 탭에서 상태 변경 (신규/확인중/수정중/해결/보류)
- Notion과 상태 양방향 동기화

#### 🔜 섹션별 진행현황 대시보드 고도화

현재 대시보드는 전체 집계만 표시한다.

- 기능그룹별 PASS/FAIL 현황 차트
- 우선순위별 완료율

## 3. 화면 구성

### 3-1. 전체 레이아웃 ✅ 구현완료

3탭 구조: 업로드(스펙 변환) | 생성 TC/테스트 실행 | 이슈 정리
상단: 다크 헤더 (TC Pilot 로고 + 프로젝트명 + 관리자 상태)
워크플로우 스텝 표시 (업로드 → 생성 TC → 테스트 실행 → 이슈 정리)

### 3-2. 탭 1: 스펙 변환 ✅ 구현완료

- 파일 업로드 영역 (드래그앤드롭)
- parseOnly 체크박스
- 변환 결과 편집 가능 테이블
- [TC 생성하기] 버튼

### 3-3. 탭 2: TC 목록 + 대시보드 ✅ 구현완료

- 진행현황 카드 (총 TC / PASS / FAIL / 진행중 / 미확인 / 완료율)
- TC 배치 목록 (생성 이력)
- 필터 (관점별 / 기능그룹별)
- TC 테이블 (P/F 드롭다운, 우선순위 툴팁 포함)
- [xlsx 다운로드] [CSV 다운로드] 버튼
- FAIL 선택 시: 오른쪽에서 이슈등록 슬라이드 패널

### 3-4. 이슈 등록 슬라이드 패널 ✅ 구현완료

- TC 데이터 자동 매핑
- 실제결과, 심각도, 스크린샷 입력
- [AI 보강] [Notion 등록] 버튼

### 3-5. 탭 3: 이슈 로그 ✅ 구현완료

- 등록 이슈 목록
- Notion 전송 상태 확인
- 심각도별/상태별 필터
- 이슈 목록 xlsx 다운로드

## 6. 성공 기준

### 6-1. 세미나 데모 시나리오 (3분) ✅ 달성 가능

1. 실제 기획서 PPT 파일을 드래그앤드롭한다 → 스펙이 자동 변환된다 (30초)
2. TC 생성 버튼을 누른다 → TC가 관점별로 자동 생성된다 (30초)
3. TC 3개를 PASS 체크한다 → 대시보드 수치가 변한다 (15초)
4. TC 1개를 FAIL 체크한다 → 이슈 패널이 열리고 TC 데이터가 채워져 있다 (30초)
5. 실제결과를 입력하고 Notion 등록을 누른다 (30초)
6. Notion을 열어서 칸반보드에 이슈 카드가 생긴 것을 확인한다 (15초)
7. 확장 비전 — Mantis 연동, Playwright 연동 아키텍처를 보여준다 (30초)

### 6-2. 핵심 메시지

"LLM은 좋은 TC 텍스트를 만들어주지만, TC 생성에서 테스트 추적, 이슈 등록까지 하나의 흐름으로 연결되는 건 서비스만 가능합니다. FAIL 한 번 누르면 이슈 템플릿이 자동으로 채워지고, 등록 버튼 하나로 Notion 칸반에 전달되는 경험은 ChatGPT에 텍스트를 복사 붙여넣기하는 것과 완전히 다른 차원의 효율입니다."
